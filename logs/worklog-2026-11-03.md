Correction: the run report first said "0 `check_flag` calls" because `run_report.py` matched
the name `checkflag`; the tool is `check_flag`. There were 34 calls, all placeholder guesses
(`flag{hidden_flag}`, `$FLAG`, …), none correct; `give_up` was never called.

**Transcript review** (`findings.md` in the run directory), in order of frequency:
1. 69 of the 101 replies without a tool call were real `<invoke>` blocks missing the
   `<function_calls>` wrapper; the harness drops them and generation runs to the token cap.
   The other 32 were prose. The rate is flat across rounds. New issue I11.
2. 104 of the 114 repeated tool calls reproduced byte-identical output; 56 were duplicate
   invokes inside one reply (up to 16 per reply). Repeats follow results the model had seen.
3. 26 of the 41 tool errors were parameters written in the tool-description schema
   (`<name>command</name>…<value>…</value>`) instead of `<command>…</command>` (I11).
4. The 3 context-length endings at 32k each came from one oversized output (a 2.6 MB `cat`
   of a binary, a 167 KB `strings`, an 11-invoke disassembly reply). At 4k, 25 of 47
   challenges would have overflowed. New issue I12: per-output cap.
5. rev/pwn: 10 of 17 never called a disassembler; 19 of 24 `disassemble_function` calls
   errored (wrong function names). web: 4 of 8 issued no HTTP command at all; one wrapped
   every command in `$'…'` quoting, so bash ran a nonexistent command 15 times.

## Notes and problems found

  egress rule; the first launch did. The launcher now creates its own security group.
- `g6e.xlarge` (L40S) had no on-demand capacity in any `us-west-2` zone at 22:26. The
  launcher tries every zone; it does not yet fall back to another instance type or wait.
- The vLLM backend logged only the model's replies before `6b08d87`; the baseline logs
  in this fork's history therefore cannot be used to measure context use.
